## M1期: 超小型CMake保険練習(1h上限)

目的(決定#13・AI境界の作業台規定): 零号機本体のCMakeLists.txtはAI提供でよいが、「作業台の中身を一度も自分の手でなぞっていない」状態を避け、**面接で「なぜCMakeか」を30秒で口頭回答できる**裏付けを作る。本体のビルド設定を書き直す練習ではない(あちらは複雑でAI提供のまま)。ここでは本体とは別の、使い捨ての最小構成だけを自分の手で書く。

- **上限1h**。詰まっても30分でAIに相談してよい(ただし完成形を丸ごとは求めず、エラーメッセージの意味を聞く)
- 手順:
  1. 零号機とは別の適当な練習フォルダ(例: `C:\CodexDev\cmake-drill`)を作り、標準出力に1行出すだけの `hello.cpp` を自分で書く
  2. 同じフォルダに `CMakeLists.txt` をゼロから書く。使ってよいコマンドは3つだけ: `cmake_minimum_required(VERSION ...)` / `project(...)` / `add_executable(...)`。外部ライブラリ(GLFW等)は一切登場しない
  3. コマンドライン、またはVisual Studioの「フォルダを開く」機能でビルドし、exeが実行できることを確認する
  4. 動いたら「なぜCMakeか」を自分の言葉で1〜2行書き留める(面接30秒回答の下書きにする)
- 本体(零号機)のCMakeLists.txtとの違いを一言で: 本体はFetchContentでGLFWを取得する等の複雑な依存管理が入るが、この保険練習は依存ゼロの最小形だけを扱う

## M3期: 値/参照の分類ドリル(VBO/VAOのRAII課題より前に実施)

C#経験者は「配列やクラスっぽいものは参照的に振る舞う」という感覚とC++の既定コピーの食い違いで分類事故を起こしやすい(C#等のマネージド言語経験者が典型的に踏むつまずきパターンである)。M3でVBO/VAOをRAIIクラスに包む前に、ここで「このコードで何が起きるか」形式の小問12問を解いて、値渡し/参照渡し/ポインタ渡し・スタック/ヒープ(スタック=関数呼び出しと共に自動で片付く置き場、ヒープ=`delete`するまで自分で管理し続ける置き場)・コピーの有無を体で覚える。**答えは書かず、自分でコードを実際に動かして確認する**(コンソールに値を出力して検証するのが一番確実)。実行にはM1のCMake保険練習で作った使い捨てフォルダ(例: `C:\CodexDev\cmake-drill`)を再利用してよい(零号機本体にドリルコードを混ぜない)。**このドリルは本体と同じC++17で行う**: cmake-drillの`CMakeLists.txt`に`set(CMAKE_CXX_STANDARD 17)`を1行足す(コマンドラインで直接ビルドするなら`/std:c++17`。保険練習の「コマンド3つだけ」規則は保険練習のときのもので、ドリル再利用時はこの1行を足してよい)。**付け忘れるとMSVCの既定はC++14になる**(この計画の環境での実測: C++14では問11が(a)(b)とも2回印字になって対比が消えた。C++17なら(b)の1回が言語保証になる)。詰まったら30分後にAIへ関数単位で相談してよい。

**C#対応表(C#経験者が踏みやすい罠を明記)**:

| C++の型・渡し方 | 挙動 | 対応するC#の感覚 | 罠 |
|---|---|---|---|
| `int`等の組み込み型を値渡し | コピーが渡る。呼び出し元は不変 | C#の値型(`int`等)の値渡しと同じ | 特になし |
| `struct`/`class`を値渡し(参照・ポインタなし) | メンバ全部がコピーされる。呼び出し元は不変 | **C#の`class`は常に参照渡しの感覚だが、C++は`struct`/`class`ともデフォルトで値渡し=コピー** | C#の癖で「クラスっぽいものは参照渡しのはず」と思い込む。C#等のマネージド言語経験者が典型的に踏む分類事故のパターン |
| `T&`(参照)で渡す | コピーなし。呼び出し元が変わる | C#の`ref`引数と同じ | 参照は「別名」であり、途中で別の変数を指し直すことはできない |
| `const T&`で渡す | コピーなし・書き換え不可 | C#に直接の対応なし | 「読むだけなのに参照渡し」の理由=コピーコストの節約 |
| `T*`(ポインタ)で渡す | ポインタ自体はコピーされるが、指す先は共有される | C#の内部的な参照渡しに近い | 指す先が有効かどうかを自分で管理する必要がある(C#にはGCがあるがC++にはない) |
| 生配列(`T arr[]`)を関数に渡す | 配列は「先頭要素へのポインタ」に変換されて渡る。要素はコピーされない | C#の配列は参照型なので挙動は近いが、**C++では「配列は値型に見えて実は特別扱い」という認識のズレが罠** | この分類事故の核心。「配列だから安全にコピーされる」ではなく「配列はポインタ化されて共有される」と覚える |
| ローカル変数 | スタックに置かれ、スコープを抜けると自動的に消える | C#の値型ローカル変数と同じ感覚(C#の`class`インスタンスはヒープ) | — |
| `new`で確保した実体 | ヒープに置かれ、`delete`するまで残り続ける | C#の`new`はGCが自動回収するが、**C++の`new`は自分で`delete`しないとメモリリークする** | M3のRAIIでこの管理を自動化する。生の`new`/`delete`を手で書く場面は最小化する |
| `std::vector`等のコンテナを値渡し | 中身の全要素がコピーされる(重い) | C#の`List<T>`は参照型なので値渡し感覚で使えるが、C++の`std::vector`はデフォルトでコピー | 大きなデータは`const std::vector<T>&`で渡す習慣をここで作る |
