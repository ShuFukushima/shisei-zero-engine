# エンジンTips対応表 — 「いま作っているもの」は実在エンジンの何なのか

目的: 黙々と手を動かす作業を「エンジンの正体を暴いていく作業」に変える。
AIは新しい概念を教えるたび、この型のTips(実在エンジンでは何か/どの高度機能につながるか)を必ず1つ添える(ルール: docs/prompts.md §1、AGENTS.md)。
この表は各マイルストーンの代表例。面接の「なぜこれを作ったの?」への回答素材でもある。

---

## M1: GPUパイプラインの入口(絵を出す)

| いま作るもの | 実在エンジンでは | この先につながる高度機能 |
|---|---|---|
| GLFWウィンドウ+ループ | エンジンの「メインループ」。Unityで `Update()` が毎フレーム呼ばれる仕組みの正体 | 固定タイムステップ(物理の安定化)、マルチスレッド化・ジョブシステム |
| VBO/VAO(頂点バッファ) | Unityの `Mesh` の実体。ドラッグ&ドロップの裏でUnityがやっていたこと | GPUインスタンシング(草を1万本描く)、動的バッチング |
| シェーダー(GLSL) | UnityのマテリアルやShaderGraphがノードの裏で生成しているもの。UE5のマテリアルエディタも最終的にはシェーダーコードになる | トゥーン調・水面・雪などあらゆる見た目表現。ポストプロセス全般 |
| テクスチャ | `Texture2D` とUVマッピングの正体 | ミップマップ、法線マップ、PBRのテクスチャ群(金属度・粗さ) |
| glDebugMessageCallback | Unityのコンソールに赤いエラーが出る仕組みをGPU側に対して自分で配管する行為 | Vulkanのvalidation layer、社内エンジンのGPUデバッグ基盤 |

## M2: 数学ライブラリ

| いま作るもの | 実在エンジンでは | この先につながる高度機能 |
|---|---|---|
| Vec3 / Mat4 の自作 | Unityの `Vector3` / `Matrix4x4`、UEの `FVector` / `FMatrix` の正体。物理・アニメ・カメラ・AIの視界判定まで、エンジンの全機能がこの上に建つ | SIMD最適化(数値計算の並列化)、クォータニオン→スケルタルアニメーション |

## M3: 3D空間とカメラ

| いま作るもの | 実在エンジンでは | この先につながる高度機能 |
|---|---|---|
| MVP行列(モデル・ビュー・投影) | Unityの `Transform` +`Camera` コンポーネントの正体。「親子関係で動く」仕組みもこの行列の掛け算 | シーングラフ、スケルタル階層(ボーン)、LOD切り替え |
| 深度バッファ | 「手前のものが奥を隠す」をUnityが黙ってやってくれていた仕組み | シャドウマッピング(深度を光から見る)、SSAO、被写界深度 |
| FPSカメラ | `Cinemachine` の最小形 | シネマティックカメラ、カメラシェイク、タイムライン演出 |
| deltaTime | Unityの `Time.deltaTime` の正体。「どのPCでも同じ速度」を作る唯一の方法 | 固定タイムステップ(物理)、スローモーション・ヒットストップ演出 |
| RenderDocでフレーム解剖 | UnityのFrame Debuggerの正体。プロの描画デバッグの標準装備 | GPUプロファイリング、ドローコール最適化 |

## M4: アセットとライティング

| いま作るもの | 実在エンジンでは | この先につながる高度機能 |
|---|---|---|
| OBJパーサー自作 | エンジンの「アセットインポーター」の最小形。Unityにファイルを放り込むと動く裏側 | glTF対応、独自バイナリ形式、アセットのストリーミング読み込み |
| 法線+Phongライティング | 全ライティングの祖先。UnityのLitシェーダーもUE5のLumenも、突き詰めればこの式の子孫 | PBR(物理ベースレンダリング)、IBL(環境光)、グローバルイルミネーション |

## M5+: 仕上げとその先

| いま作るもの | 実在エンジンでは | この先につながる高度機能 |
|---|---|---|
| シャドウマッピング | ほぼ全ゲームの影は今もこの原理(カスケード分割などの改良版) | CSM(カスケードシャドウ)、レイトレーシングの影 |
| デモシーン構成 | 「シーン」概念の最小形 | シーン管理、ECS、エディタ(→ROADMAP.md 第3フェーズ) |
