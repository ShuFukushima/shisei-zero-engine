# SourceTree操作ガイド(このプロジェクト用)

学校配布の「GitHub操作説明」PDF(§2 個人製作での使用)と同じやり方で運用する。
Unityの時との違いは2点だけ: **リポジトリは先にローカルに存在している**こと、**gitignoreはC++用を自作済み**(Unity用のプルは不要)なこと。

---

## §1 初回セットアップ(1回だけ)

1. GitHubのサイトで New repository を作成
   - 名前: `shisei-zero-engine`(ローカルのフォルダ名と揃える)
   - **Public** を選ぶ
   - **「Add a README file」「Add .gitignore」「Choose a license」はすべてチェックを入れない**(空のまま作る。ローカルに実物があるので、GitHub側にファイルを作ると衝突する)
2. 作成完了画面でURLをコピー(いつもUnityで使っているのと同じ種類。SSH設定済みならSSH)
3. SourceTreeで「新規」→「**既存のローカルリポジトリを追加**」→ `C:\CodexDev\shisei-zero-engine` を指定
   (クローンではなく「追加」。ローカルに既にあるため)
4. リポジトリ設定 → リモート → 追加: リモート名 `origin`、URLを貼り付け、自分のアカウントを選択
5. プッシュボタン → `main` にチェック → プッシュ
6. GitHubのページを開き、READMEが表示されていれば完了

※ LICENSEファイルは作成時にチェックを入れない代わりに、M5(仕上げ)でローカルにMITライセンスのLICENSEファイルを追加してコミットする(PLAN.md §4 M5の成果物)。

## §2 毎回の締め(単元・作業セッションが終わるごとに必ず)

PDFのp52〜57「コミット&プッシュ」と同じ操作。

1. SourceTreeを開き、左の「ファイルステータス」で今日の変更ファイルを確認する
   (見覚えのないファイルが大量に出ていたら、コミットせずAIに相談。`build/` は .gitignore 済みなので出ないのが正常)
2. **AI関与の台帳照合**: このコミットに含まれるAI関与(コード開示・作業台・文書起草等)が docs/disclosure-log.md に記録されているか、コミット対象ファイルと台帳の「対象ファイル・箇所」欄を1件ずつ突き合わせる。記録漏れがあればその場で追記してからコミットする。AI関与の無いコミットは「無し」と確認するだけでよい
3. コミットするファイルを選んで「**インデックスに追加**」
4. コミットメッセージを書いて「コミット」。書き方の規律(gitの慣習: 2行目は必ず空行):
   - 1行目: 何をしたか(例: `三角形の描画: VBOとシェーダーを実装`)
   - 2行目: **空行**(gitはここが空行でないと表示が崩れる)
   - 3行目: **何を理解したか**を1行(例: `理解: 頂点データはGPUのメモリに転送してから使う`)
5. 「プッシュ」→ `main` にチェック → プッシュ
6. GitHubのページで反映を確認(この積み重ねが就活での証拠になる)
7. **台帳のハッシュ更新**: docs/disclosure-log.md に「コミット前」と書いた行が残っていれば、SourceTreeのログ(History)でそのコミットのハッシュ先頭7桁を確認し、台帳の該当セルを置き換えて再コミット→プッシュまで行う(次回に回すと忘れるため、その場で完結させる)

## §3 困ったとき

- **プッシュが拒否された**: 先に「プル」してからプッシュし直す
- **間違えてコミットした・衝突した**: PDFの「§4 間違えてしまった時」(p104〜)の該当ページを見る。分からなければ**操作する前に**AIに状況を貼って相談する(慌てて操作しない)
- **コミットし忘れて日をまたいだ**: 気づいた時点でそのままコミットしてよい(理解の1行は思い出せる範囲で)
